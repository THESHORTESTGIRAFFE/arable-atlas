# Arable Atlas

Arable Atlas helps farmers explore modeled soil properties, check a five-day forecast, save field reports, and discuss their land with **Plotty 🌱**.

## Implemented workflow

1. Open **Analyze**, select a map point or use a JPG photo's GPS metadata.
   Use **Try the demo field · Harare outskirts** to select the prepared demo coordinates.
2. Review SoilGrids topsoil estimates and Plotty's crop suggestions.
3. Add an optional crop and planting date, then refresh the forecast and field action plan.
4. Save a named field report. Open an older report to compare previous observations.
5. Choose **Discuss this field with Plotty**. Plotty receives the current report, forecast, and recent conversation.

The dashboard and chat support **English, Shona, Ndebele, French, Spanish, and Mandarin Chinese (Simplified Chinese)**. Language preference persists in this browser. Existing chat messages stay in their original language; new replies use the selected language. Switching languages on the dashboard translates existing crop advice through Gemini without repeating the soil lookup. Local agricultural terminology should be reviewed with fluent speakers before a public launch.

Browser speech recognition is enabled for English, French, Spanish, and Chinese when the recognition API exists; actual availability depends on the browser and its recognition service. Shona and Ndebele fall back to typing. Read-aloud controls appear only when an installed voice matches the message language.

## Data and limitations

- SoilGrids supplies modeled properties on a 250 m grid for the top 0–5 cm. These are estimates, not laboratory measurements.
- Soil lookups use the working WCS map service, bypassing the paused REST API. Native-grid GeoTIFF subsets and their download timestamps are stored in `instance/soil_cache`; subsequent nearby lookups sample those maps locally. Partial results list missing properties. Masked pixels, including all-zero WCS background pixels, are shown as unavailable.
- **Enter soil-test results** accepts pH, sample depth, and optional sample date, nitrogen, carbon density, and texture fractions. These are labeled user-entered and unverified. Their original units and depths are retained in saved reports and Plotty's context. Texture fractions must be supplied together and total 100% (±1%). Missing properties remain missing.
- Organic carbon density (`ocd`) is converted to kg/m³; total nitrogen is converted to g/kg. Soil moisture is **not measured**. Total nitrogen is not used to calculate a fertilizer dose.
- Photo uploads only extract GPS coordinates. They do not inspect soil or diagnose crop disease. Temporary uploads are deleted after lookup, and uploads are limited to 10 MB.
- OpenWeatherMap's five-day, three-hour forecast is aggregated by the field's local date. Daily min/max, accumulated rain, and maximum wind are shown; partial days are marked with an asterisk. Forecast responses are cached for ten minutes.
- Field actions expose simple rain, heat, frost, and wind thresholds. They are general inspection guidance; no crop-specific irrigation quantities or validated seasonal suitability scores are calculated. A failed weather lookup produces no weather actions.
- Crop suggestions are generated by Gemini and require local verification. A five-day forecast does not establish seasonal climate or suitability.

Sources: [ISRIC property units](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html), [OpenWeatherMap forecast API](https://openweathermap.org/forecast5).

## Prepare soil data for a demo

Download a square native-grid region centered on your demonstration location before presenting:

```powershell
.venv\Scripts\python prefetch_soil.py --lat -17.9 --lon 31.05 --radius-km 10
```

This fetches six real maps, at 250 m resolution and 0–5 cm depth, for a roughly 20 km-wide area. The included demo button uses `-17.9, 31.05` near Harare. This checkout already has the surrounding maps downloaded. They are runtime data ignored by Git: copy `instance/soil_cache` to a deployment or run prefetch on that host.

The command reports each layer's status and exits unsuccessfully if any map failed. It does not generate fictional sample values or call Gemini. A downloaded region can include masked urban/water areas with no soil data; the demo point is an actual valid cell. `--refresh` replaces the exact requested region; `--cache-dir` selects a different output directory. Radius is the half-width of the native projected square, limited to 0.25–50 km.

Set `SOIL_OFFLINE=true` in `.env` to disable all new WCS requests and use downloaded soil maps only. Weather, reverse geocoding, Gemini, and web map tiles still require internet. The app is not fully offline.

Maps retain their original download dates and are reused until explicitly replaced. SoilGrids represents a static soil model; download time is not the date of a field measurement. Coverage is sampled using the returned raster's coordinate system, and incomplete/missing areas are not filled with nearby measurements. Attribution: **ISRIC SoilGrids, CC BY 4.0**. [WCS documentation](https://docs.isric.org/globaldata/soilgrids/wcs.html), [data and citation](https://isric.org/explore/soilgrids).

## Run locally

Python 3.10+ is recommended.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r req.txt
Copy-Item .env.example .env
# Edit .env with your API keys and a stable random SECRET_KEY.
.venv\Scripts\python app.py
```

Open http://localhost:5000. For Waitress, run `.venv\Scripts\python run_production.py`.

Configuration:

```env
GEMINI_API_KEY=your_google_gemini_api_key
GEMINI_MODEL=gemini-3.5-flash-lite
OPENWEATHER_API_KEY=your_openweather_api_key
DATABASE_URL=sqlite:///agrimap.db
SECRET_KEY=your_stable_random_secret
SOIL_OFFLINE=false
# Optional: SOIL_CACHE_DIR=C:/path/to/soil_cache
```

`GEMINI_MODEL` must name a text-generation model available to your Google project. The OpenWeatherMap key must have access to the five-day forecast endpoint.

## USSD and SMS demonstration

Open `/ussd` or select **USSD / SMS** in the navigation. This is a browser-based feature-phone simulator, not a live shortcode. It does not ask for a real telephone number, send carrier messages, or use SMS credits.

1. Press **Dial demo menu**.
2. Choose `2` for a soil SMS, then `1` for the cached Harare demonstration area.
3. The menu ends immediately. A background worker creates a short message in the simulated inbox.
4. Dial again to try a weather SMS (`1`), ask Plotty a question (`3`), or change language (`5`). All six languages are available. Weather and soil use templates with no AI call; questions use the existing Gemini credentials and may incur AI API charges.

Soil summaries use already-cached SoilGrids values only, never new WCS downloads. Missing weather or soil data is stated explicitly. Each simulated inbox is scoped to the signed browser session. Duplicate terminal requests create only one message. The demo limits requests to ten per browser session per hour, with a small shared worker queue. Sessions expire after three minutes. Requests interrupted by a server restart eventually show as failed; the farmer can dial again.

SMS text targets at most two segments. The segment estimator counts GSM-7 extension characters and Unicode UTF-16 units. Long replies keep complete sentences or fall back to a request for a more specific question rather than cutting an instruction in half. **Estimated segments are not a price quote.** [SMS encoding reference](https://www.twilio.com/docs/glossary/what-sms-character-limit).

The browser talks to `/api/ussd/session` and polls `/api/ussd/inbox`; these are simulator endpoints authenticated by browser cookies, not public carrier callback endpoints. Live rollout needs country/network selection, provider provisioning, a registered shortcode and SMS sender, public HTTPS, authenticated gateway callbacks, durable workers and delivery receipts, plus phone-based consent and opt-out handling. No provider has been selected or live delivery configured.

After source changes, stop and restart Waitress; it does not reload Python modules automatically. If `/contact` or other pages show a generic Waitress error after an update, restart the process in its terminal with `.venv\Scripts\python run_production.py`. The contact page's existing address, email, phone, and office hours are unchanged.

## Saved reports and privacy

Reports are stored in SQLite and scoped to a signed browser session, rather than a user account. Keep `SECRET_KEY` stable. Clearing browser cookies loses access to that session's saved reports; clearing local storage removes its current report and language preference. This is a prototype ownership mechanism, not cross-device account authentication.

The latest report and selected language are cached in local storage, and chat history is kept in session storage. Reloading a page still requires a connection; this is not a complete offline application. Soil/forecast data and recent messages are sent to Gemini when you ask Plotty about your field. Coordinates are sent to SoilGrids, OpenWeatherMap, and the reverse geocoder for the requested analysis.

The additive `FarmProfile` table stores report snapshots and ownership without altering existing `FarmPlot` rows. Old unowned records remain in the database but are not exposed to newly created sessions.

## Project map

- `app.py`: Flask pages, validation, analysis, chat, plan, translation, and saved-report endpoints.
- `utils.py`: EXIF coordinates, SoilGrids units, and Gemini conversation handling.
- `soil_provider.py`: WCS subsets, atomic persistent raster cache, and native-grid sampling.
- `prefetch_soil.py`: download a real region before a demonstration.
- `weather.py`: cached forecasts and deterministic field-check rules.
- `translations.py`: six language catalogs shared with the browser.
- `models.py`: SQLAlchemy plots and session-owned report snapshots.
- `static/js/`: language preference, dashboard flow, and stateful chat.

Legacy `routes.py`, the files under `routes/`, `db.py`, and `data/soil_model.py` are not registered by the running Flask application.
